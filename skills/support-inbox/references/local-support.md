# Local support events and model billing

Choose **hosted autopilot** when customers need an answer while the owner's computer is offline. Choose **local drafts** when a teammate wants to review answers on their machine. Customers keep writing to the same support address or number. Do not enable a second automatic sender.

## Model access

- Hosted: the workspace admin links their eligible paid plan to the provider's API organization, creates a project API key there, then privately enters it in Swiss-Knife's Support AI provider credential form. Save the key, test the connection, confirm the result identifies the workspace key, then select the provider and a model it can access. A listing test is not a generated answer: verify a reply on an owner-controlled conversation. Confirm usage in the linked provider organization. Leave an existing working credential in place until its replacement has been tested. Never request secrets in chat.
- [OpenAI eligibility and billing](https://developers.openai.com/api/docs/guides/chatgpt-api-credits): eligible Pro and Business plans can claim API credits. These do not increase signed-in Codex limits or pay for API-key Codex usage. [Claude eligibility and billing](https://support.claude.com/en/articles/17154008-monthly-api-credits-for-max-ultra-and-team-plans): eligible Max, Ultra and Team plans can link a Console organization. Verify eligibility and remaining balance with the provider. A subscription receipt alone is not an API credential.
- Local: sign in to the chosen CLI on the operator's machine (Codex or Claude Code). In this mode the CLI handles its own authentication; the watcher never copies a chat login to Swiss-Knife. The separate Swiss-Knife read token grants inbox access and cannot pay for a model. For a local guide set SWISS_SUPPORT_GUIDE to a private file containing only approved support policies (standalone drafts). An interactive Claude session can read the guide explicitly. Do not infer policy from old tickets.

## Local setup

Use Node 22+ and the installed plugin's `bin/support-channel.mjs` (called BRIDGE below). Resolve its absolute path before registering the channel. First run `node "$BRIDGE" --demo --claude-draft` or `node "$BRIDGE" --demo --codex`. Both produce a draft and send nothing. Set SWISS_SUPPORT_CODEX_MODEL if the account cannot use the CLI's default model.

1. Use workspace_whoami and inbox_list to select one workspace and support inbox. Set SWISS_SUPPORT_WORKSPACE and SWISS_SUPPORT_INBOX to their IDs in the launching shell. Set SWISS_SUPPORT_TOKEN_FILE to a private file (mode 0600) holding a Swiss-Knife viewer/read token with the narrowest app access that can read that inbox. Workspace-wide inboxes cannot use an app-only token. The watcher filter is not an authorization boundary. The token is sent only to the hosted Swiss-Knife MCP endpoint. Do not put model keys in this file. Run `node "$BRIDGE" --check` to verify the token can see the selected support inbox without starting a model.
2. For a Claude **channel**, register the stdio command with `claude mcp add --scope local support-channel -- node "$BRIDGE"` in a dedicated support directory, then start a channel-enabled session in that directory. Follow [Claude's custom channel instructions](https://code.claude.com/docs/en/channels); a development channel may require `claude --dangerously-load-development-channels server:support-channel` and a managed organization can disallow channels. Use only this trusted local server. Start with the script's `--demo` argument for a synthetic notification, then remove that argument for live use. Keep the Swiss-Knife plugin connected to read the conversation. The channel sends IDs; customer text is untrusted.
3. Alternatively, run `node "$BRIDGE" --codex` or `node "$BRIDGE" --claude-draft` for standalone local drafts on stdout. Each draft uses a fresh CLI session. This does not inject messages into an existing Codex desktop chat.
4. Send a fresh message from a controlled handset. Watch for the selected inbox and message ID. Re-read before sending: if hosted AI or a person already replied, stop. Preview and approve a real reply through the support-inbox skill. Stop the local process to disconnect; revoke its read token if retiring it.

The watcher polls open, unassigned conversations every 15 seconds and looks for the latest still-unanswered public customer message since startup. Several quick messages may coalesce; a hosted answer before the next poll suppresses the event. This is a live drafting aid, not a durable feed of every message. Restarting does not replay offline history. Keep hosted autopilot for unattended delivery.
